# context-recall

分类: 效率（AVAILABLE）

你每次启动都是零记忆。而过去的工作产出都落在 `~/.frago/data/<语义目录>/` 下：一次调研的笔记、一份 spec、一个 notebook 账本、几份中间数据。

你记得的通常只是一个关键词（"cxmt 那个视频"、"session workbench"），而目录名带日期前缀、带连字符、带你没记住的限定词。列一遍目录再挨个猜哪个是，等于每次回到旧任务都要先付一轮探索。

`{{frago_launcher}} context` 把"关键词 → 目录 → 目录里有什么 → 索引型小文件的全文"压成一条命令。

## 用法

```bash
{{frago_launcher}} context data:<关键词>              # 定位并摊开上下文
{{frago_launcher}} context data:<关键词> --paths-only # 只要路径和文件清单，不吐内容
{{frago_launcher}} context data:<关键词> --json       # 机器可读
```

`data:` 是命名空间前缀，指 `~/.frago/data`。前缀不可省——省了会报错并提示你补上。

## 它输出什么

命中目录的绝对路径、命中方式、完整文件清单（体积与修改时刻），以及索引型小文件的**全文**。

`notebook.md` / `README.md` / `spec.md` 这类入口文件优先吐出。单个文件超过 16 KB、或本次全文总量超过 64 KB 之后的文件只列路径，并在清单里逐个标明原因（"大文件，按需自行 Read"）。被留在外面的东西一定看得见——NEVER 把截断当成"全部内容就这些"。

## 关键词怎么写

匹配是分层的，一层命中就定分，分数区间不重叠。你看命中方式那一行就知道这个结果是查到的还是猜到的。

| 层 | 分 | 例 |
|---|---|---|
| 完全同名（自动剥掉日期前缀） | 100 | `cxmt-ipo-video` → `20260725-cxmt-ipo-video` |
| 名字以关键词开头 | 90 | `cxmt` → 同上 |
| 名字含关键词 | 80 | `ipo` → 同上 |
| 关键词每个词都在名字里，不计顺序 | 70 | `workbench session` → `20260728-agent-session-workbench` |
| 字符按序出现（缩写、漏字） | 60 | `sesswrkbench` → 同上 |
| 相似度兜底（拼写差异） | ≤60 | `cxmt-ipo-vidoe` → `20260725-cxmt-ipo-video` |

大小写、连字符还是下划线都不影响匹配。

## 三种失败，各自怎么办

**多个目录都够分且没有完全同名** —— 命令列出全部候选并拒绝替你选，退出码 1，每个候选都给成可直接执行的命令。带更精确的词再来一次，NEVER 从候选里随便挑一个往下做。

**一个都没命中** —— 命令列出最接近的几个名字。换个说法再试；确实没有就是这件事还没落过盘。

**`~/.frago/data` 不存在** —— 报错并给出创建命令。

## 与沉淀侧的关系

`save-conversation` 那类技能把经验写进 `~/.frago/data/<目录>/notebook.md`，这条命令是它的读回口。做完一件事沉淀下来，下次冷启动一句 `{{frago_launcher}} context data:<关键词>` 就能接上——闭环的两端要配套用。
