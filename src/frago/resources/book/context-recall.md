# context-recall

分类: 效率（AVAILABLE）

你每次启动都是零记忆。而过去的工作产出都落在 `~/.frago/data/<语义目录>/` 下：一次调研的笔记、一份 spec、一个 notebook 账本、几份中间数据。

你记得的通常只是一个关键词（"cxmt 那个视频"、"session workbench"），而目录名带日期前缀、带连字符、带你没记住的限定词。列一遍目录再挨个猜哪个是，等于每次回到旧任务都要先付一轮探索。

`{{frago_launcher}} context` 告诉你这个词落在哪儿——**它不会打印任何文件正文**，读什么由你定。

## 用法

```bash
{{frago_launcher}} context data:<关键词>          # 在 ~/.frago/data 下找
{{frago_launcher}} context data:<关键词> --json   # 机器可读
```

`data:` 是命名空间前缀，指 `~/.frago/data`——那一层的每个目录都是一件工作的产出，
所以命中即有意义。**知道要找的是产出物就带上前缀**，这是快路径。

## 它输出什么：三类命中，各自成段

| 段 | 内容 |
|---|---|
| 目录命中 | 名字匹配的目录，带文件数、体积、最后修改、命中方式 |
| 文件名命中 | 名字匹配的文件 |
| 可读内容命中 | 正文含关键词的文档，**按命中次数从多到少**，每条带路径、次数、一行摘要 |

看完自己决定 Read 哪个。清单里路径都是全的。

**为什么不吐全文。** 这条命令原本会把命中目录里的小文件整篇贴出来，想的是省掉你再多轮 Read。第一次真用就翻车：一次调用六万多字符、约合两万 token，而其中真正被需要的只有一两篇。剩下的是替你做了你没要求的决定，还把你的预算花光了。

**内容命中为什么只按次数排。** 排最前的未必最有价值——一份 ffmpeg 的文件拼接清单会因为路径里带着关键词而拿到上百次命中，真正有内容的笔记只有十次。但按次数排是**可解释**的，你看得懂这个序怎么来的；而每条都带摘要，噪音在摘要里自己暴露（`file '/x/…/S001.wav'` 一眼就是机器清单）。规则透明加证据在场，比一个猜出来的聪明排序可靠。

**内容检索只走人写的格式**（md / txt / yaml / csv 等）。JSON、JSONL、HTML 这些机器格式排除在外，它们命中的多半是路径和标识符。被排除的命中数量会一并报出来，NEVER 让"没找"看起来像"找了没有"。

## 不带前缀是另一回事，不是简写

`{{frago_launcher}} context <关键词>` 不等于 `data:<关键词>`。它的含义是"我不知道
在哪儿，把整个 `~/.frago` 翻一遍"。

那棵树是上万个目录、几十 GB 的量级，绝大多数是机器用的——浏览器 profile、HTTP
缓存、recipe 的依赖树、日志轮转。所以这一趟既慢（实测数秒，冷缓存下更久），命中
也脏（那些目录的名字照样会跟关键词撞上，但没一个是上下文）。

因此它会先问一句再动手。非交互场合（你在脚本或工具调用里跑）问不了，命令直接
拒绝并告诉你两条出路：带上前缀，或者显式 `--yes`。

```bash
{{frago_launcher}} context <关键词> --yes   # 确认全盘搜索
```

结果里会报出扫过多少目录、跳过多少构建产物目录，扫描范围始终可见。

## 关键词怎么写

名字匹配是分层的，一层命中就定分，分数区间不重叠。命中方式那一列会告诉你这个结果是查到的还是猜到的。

| 层 | 分 | 例 |
|---|---|---|
| 完全同名（自动剥掉日期前缀） | 100 | `cxmt-ipo-video` → `20260725-cxmt-ipo-video` |
| 名字以关键词开头 | 90 | `cxmt` → 同上 |
| 名字含关键词 | 80 | `ipo` → 同上 |
| 关键词每个词都在名字里，不计顺序 | 70 | `workbench session` → `20260728-agent-session-workbench` |
| 字符按序出现（缩写、漏字） | 60 | `sesswrkbench` → 同上 |
| 相似度兜底（拼写差异） | ≤60 | `cxmt-ipo-vidoe` → `20260725-cxmt-ipo-video` |

大小写、连字符还是下划线都不影响匹配。内容检索则是字面量匹配，关键词里的 `.` `(` `+` 不当正则解释。

## 每段都有上限，超出会报数

三段各有列出条数的上限，超出时写明"另有 N 个未列出"。看到这行就说明该换更精确的词，NEVER 把列出的当成全部。

`~/.frago/data` 不存在时报错并给出创建命令；ripgrep 不在 PATH 上时内容那一段搜不了，会明说，但名字那两段照常出结果。

## 与沉淀侧的关系

`save-conversation` 那类技能把经验写进 `~/.frago/data/<目录>/notebook.md`，这条命令是它的读回口。做完一件事沉淀下来，下次冷启动一句 `{{frago_launcher}} context data:<关键词>` 就能找回来——闭环的两端要配套用。
